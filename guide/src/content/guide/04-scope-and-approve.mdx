## Goal

In lesson 03 the agent wrote a file the moment the model asked. It is offered every workspace tool, `delete` included, and nothing stands between the model and a write.

Add two defaults:

- **Scoped access to tools**: the model is only offered the tools on an allowlist. `delete` is not on it.
- **Approval gates before write actions**: `write`, `edit` and `exec` wait until a person selects **Approve** or **Reject**.

## Starting point

Continue in the template from lesson 03:

```bash
cd lab/template
```

The approval UI is already in the template. The browser shows an Approve / Reject card for any tool the server says needs approval, and sends your decision back over the WebSocket. Until the server has a gate, that list is empty and no card appears.

## Steps

1. Create the approval gate.
2. List the allowed and gated tools.
3. Scope and gate the tools.
4. Connect the gate to the browser.

### 1. Create the approval gate

Create this file:

```txt
src/approvals.ts
```

Add:

```ts
import type { JsonObject, ToolRegistration } from "@earendil-works/pi-durable";
import type { ApprovalDetails } from "./protocol";

/**
 * Approval gate: a wrapper that parks a tool call until an operator
 * approves or rejects it.
 *
 * Pi Durable has no approval primitive of its own, so the gate lives in the
 * tool's `execute`. The call publishes `{ approval: "pending" }` through
 * `api.details()`, which reaches every connected client as a
 * `tool_execution_update`, and waits on an in-memory resolver keyed by the
 * call id. `resolve()` settles it from the socket. A denied call returns an
 * `isError` result so the model knows the action did not happen.
 *
 * The wait is in memory, so a gated tool is `replay: "unsafe"`: if the
 * object is evicted while a call is parked, the model gets an interrupted
 * result instead of the tool running twice.
 */
export class ApprovalGate {
  readonly names: readonly string[];
  readonly #pending = new Map<string, (approved: boolean) => void>();

  constructor(names: readonly string[]) {
    this.names = names;
  }

  /** The given tools, with the gated ones wrapped. */
  wrap(tools: readonly ToolRegistration[]): ToolRegistration[] {
    return tools.map((tool) =>
      this.names.includes(tool.name) ? this.#gate(tool) : tool
    );
  }

  /** Call ids waiting for a decision. */
  pending(): string[] {
    return [...this.#pending.keys()];
  }

  /** Settle a parked call. Returns false when nothing was waiting. */
  resolve(callId: string, approved: boolean): boolean {
    const settle = this.#pending.get(callId);
    if (!settle) return false;
    this.#pending.delete(callId);
    settle(approved);
    return true;
  }

  #gate(tool: ToolRegistration): ToolRegistration {
    const pending = this.#pending;
    return {
      ...tool,
      replay: "unsafe",
      description: `${tool.description}\n\nThis tool needs operator approval. The call waits until an operator approves or rejects it; a rejected call does nothing.`,
      async execute(args, api, context) {
        const details = (approval: ApprovalDetails["approval"]) =>
          api.details({ approval, args: args as JsonObject }, context);

        api.output("Waiting for operator approval…\n");
        await details("pending");

        const approved = await new Promise<boolean>((settle) => {
          pending.set(api.callId, settle);
          context.abortSignal?.addEventListener(
            "abort",
            () => {
              pending.delete(api.callId);
              settle(false);
            },
            { once: true }
          );
        });

        if (!approved) {
          await details("denied");
          return {
            output: [
              {
                type: "text",
                text: `The operator rejected this ${tool.name} call. Do not retry it; tell the user it was not approved.`
              }
            ],
            isError: true
          };
        }

        await details("approved");
        api.output("Approved.\n");
        return tool.execute(args, api, context);
      }
    };
  }
}
```

How it works:

- `wrap()` gives each gated tool an `execute` that waits before it runs the real one.
- While it waits, it publishes `{ approval: "pending", args }` with `api.details()`. Pi streams that to every connected browser, which shows the card.
- `resolve()` ends the wait when the browser sends Approve or Reject.
- A rejected call returns an error result, so the model knows the action didn't happen and tells the user.

<Callout type="note" title="How Cloudflare does this">
Each user's agent is one Durable Object: a single instance that holds the session, the parked tool call and the browser's WebSocket together, so the decision always reaches the call that is waiting for it. Gated tools are `replay: "unsafe"`: if the object restarts while a call waits, the model gets an interrupted result instead of the tool running twice.
</Callout>

### 3. Scope and gate the tools

Find these lines:

```ts
      // Lesson 04: offer only the TOOLS, and gate the APPROVAL_REQUIRED ones.
      const tools = createWorkspaceTools(this.workspace);
```

Replace them with:

```ts
      const tools = this.approvals.wrap(
        createWorkspaceTools(this.workspace).filter((tool) =>
          TOOLS.includes(tool.name)
        )
      );
```

The filter is the scope. A tool that isn't in `TOOLS` is never registered, so the model can't call it and never even sees it. `wrap()` then puts the gate in front of the tools in `APPROVAL_REQUIRED`.

<Callout type="note" title="How Cloudflare does this">
`exec` stays in `TOOLS`, but it is sandboxed: each call runs in a fresh Dynamic Worker, created through the `LOADER` binding in `wrangler.jsonc`, with the workspace mounted and no internet access.
</Callout>

<Details summary="Complete src/server.ts after this lesson">

```ts
import { DurableObject } from "cloudflare:workers";
import { Workspace, type DurableObjectStorageLike } from "@cloudflare/computer";
import { WorkerJavaScriptBackend } from "@cloudflare/computer/backends/worker-javascript";
import { createGitClient } from "@cloudflare/computer/git";
import { createGitModule } from "@cloudflare/computer/modules/git";
import { createModels } from "@earendil-works/pi-ai/models";
import { createRegistry, Harness } from "@earendil-works/pi-durable";
import { routeAgentRequest } from "agents";
import { PiHarness } from "agents/harness/pi";
import { Lifecycle } from "agents/lifecycle";
import { createAI } from "agents/models/pi-ai";
import { WebSockets } from "agents/websockets";
import { PiSessionSockets } from "./sockets";
import { createWorkspaceTools, JAVASCRIPT_BACKEND } from "./workspace";
import { ApprovalGate } from "./approvals";

// Scoped access to tools: the only workspace tools this agent is offered.
// `delete` is left out, so the model never sees it.
const TOOLS = ["read", "ls", "find", "grep", "write", "edit", "exec"];

// Approval gates: these tools wait for an operator before they run.
const APPROVAL_REQUIRED = ["write", "edit", "exec"];

const MODEL_ID = "@cf/zai-org/glm-5.3-flash";

const PREAMBLE =
  "You are a concise assistant. You have a durable workspace at /workspace: read, write, edit, list (ls), find and grep files there, and run JavaScript modules in it with exec, which can also use git. Paths are absolute. Use tools whenever they can answer the request, and explain their results plainly. If a tool you need is not available, say so.";

/** One agent instance per user, backed by one Durable Object. */
export class Agent extends DurableObject<Env> {
  // Identity: every model call goes through this agent's AI Gateway.
  readonly ai = createAI({ binding: this.env.AI, id: this.env.AI_GATEWAY_ID });
  // A durable filesystem on the object's SQLite, beside pi's own tables.
  // `exec` runs JavaScript modules in a fresh Dynamic Worker per call, with
  // no network of its own. `git` turns on `workspace.git`, which the `ws:git`
  // module calls in the host; `allowNetwork` lets it clone, fetch and push.
  readonly workspace = new Workspace({
    storage: this.ctx.storage as unknown as DurableObjectStorageLike,
    git: createGitClient(),
    backends: [
      new WorkerJavaScriptBackend({
        id: JAVASCRIPT_BACKEND,
        loader: this.env.LOADER,
        root: "/workspace",
        access: "read-write",
        modules: { "ws:git": createGitModule({ allowNetwork: true }) }
      })
    ]
  });
  readonly registry = createRegistry();
  readonly harness = new PiHarness({
    harness: async ({ storage, context, onWake }) => {
      const tools = this.approvals.wrap(
        createWorkspaceTools(this.workspace).filter((tool) =>
          TOOLS.includes(tool.name)
        )
      );
      // pi's own extension: the system prompt and the tools.
      this.registry.install({
        name: "agent",
        sections: [{ key: "preamble", render: () => PREAMBLE, tag: false }],
        tools
      });
      const models = createModels();
      models.setProvider(this.ai.provider);
      return Harness.open(
        storage,
        {
          models,
          registry: this.registry,
          onWake,
          settings: {
            // Identity: every model request carries the agent and the user,
            // which AI Gateway records as metadata on its log.
            stream: {
              metadata: {
                agent_id: this.env.AGENT_ID,
                user_id: this.ctx.id.name ?? this.ctx.id.toString()
              }
            },
            // pi doubles the delay before each retry: 1, 2, 4, 8 and 16 seconds,
            // so a rate-limited model gets about 30 seconds to recover.
            retry: { enabled: true, maxRetries: 5, baseDelayMs: 1000 }
          },
          onReport: (error) => console.warn("pi report", error)
        },
        context
      );
    },
    defaults: { model: this.ai(MODEL_ID), thinkingLevel: "low" }
  });

  // App glue, not the harness: how this app puts sessions on a socket.
  // The sockets carry Approve and Reject from the browser to the gate.
  readonly approvals = new ApprovalGate(APPROVAL_REQUIRED);
  readonly sockets = new PiSessionSockets(
    this.harness,
    this.registry,
    (tag) => this.ctx.getWebSockets(tag),
    { approvals: this.approvals }
  );
  readonly webSockets = new WebSockets(this.sockets.options());
  readonly lifecycle = Lifecycle.install(this)
    .use(this.webSockets)
    .use(this.harness);

  /** Host startup, after the harness has opened pi. */
  async onStart(): Promise<void> {
    await this.sockets.reattach();
  }
}

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    if (new URL(request.url).pathname === "/api/agent") {
      // Who this deployment is, for the client's header.
      return Response.json({
        agent: env.AGENT_ID,
        gateway: env.AI_GATEWAY_ID,
        model: MODEL_ID
      });
    }
    try {
      return (
        (await routeAgentRequest(request, env, { cors: true })) ??
        new Response("Not found", { status: 404 })
      );
    } catch (error) {
      console.error("Agent request failed", error);
      return Response.json(
        { error: error instanceof Error ? error.message : String(error) },
        { status: 500 }
      );
    }
  }
} satisfies ExportedHandler<Env>;
```

## Run and verify

Stop the dev server with **Ctrl+C**, then start it again:

```bash
pnpm start
```

Open [http://localhost:5173](http://localhost:5173). The **Tools** panel lists seven tools. `delete` is gone, and `write`, `edit` and `exec` carry an **Approval** badge.

1. Select **Write a file** and send it. An **Approve write?** card appears with the path and the content. Nothing is written yet. Select **Approve**: the write runs, then the agent reads the file back.
2. Select **Delete a file** and send it. There is no `delete` tool, so the model tries `exec` instead, and the gate catches it: **Approve exec?**. Select **Reject**. The agent tells you the delete wasn't approved, and the file is still there.
3. Select **Fetch a URL** and send it, then approve the `exec` call. The module runs, and `fetch()` fails with "This worker is not permitted to access the internet".

![The Approve write? card, with the Tools panel showing Approval badges on write, edit and exec](/images/approval-gate.png)

## Success check

You are ready for the next lesson when:

- `write`, `edit` and `exec` calls wait for Approve or Reject.
- Rejecting a call leaves the workspace unchanged, and the agent says it wasn't approved.
- `delete` is not in the Tools panel.
- `fetch()` inside `exec` fails with "not permitted to access the internet".
