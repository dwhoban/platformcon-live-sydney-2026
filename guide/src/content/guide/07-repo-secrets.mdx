## Goal

Stamp the agent's code and ship it. One `terraform apply` generates a repository from the template, gives it the secrets and variables its deploy workflow needs, and commits the agent's name to it. That commit starts the workflow, which deploys the agent to the Worker from lesson 02.

## Starting point

Switch back to the Terraform folder:

```bash
cd ../terraform
```

## Steps

1. Create the repository, secrets, variables and stamp.

### 1. Create the repository, secrets, variables and stamp

Create this file:

```txt
github.tf
```

Add:

```hcl
# The agent's code: a new repository generated from the template.
resource "github_repository" "agent" {
  name        = var.agent_name
  description = "AI agent ${var.agent_name}, stamped from ${var.github_owner}/${var.template_repo}"
  visibility  = "private"

  template {
    owner      = var.github_owner
    repository = var.template_repo
  }
}

# What the deploy workflow needs to deploy to your Cloudflare account.
resource "github_actions_secret" "cloudflare_api_token" {
  repository  = github_repository.agent.name
  secret_name = "CLOUDFLARE_API_TOKEN"
  value       = var.cloudflare_api_token
}

resource "github_actions_secret" "cloudflare_account_id" {
  repository  = github_repository.agent.name
  secret_name = "CLOUDFLARE_ACCOUNT_ID"
  value       = var.cloudflare_account_id
}

# Identity: the name the workflow deploys under, and the gateway its model
# calls go through.
resource "github_actions_variable" "agent_name" {
  repository    = github_repository.agent.name
  variable_name = "AGENT_NAME"
  value         = var.agent_name
}

resource "github_actions_variable" "ai_gateway_id" {
  repository    = github_repository.agent.name
  variable_name = "AI_GATEWAY_ID"
  value         = cloudflare_ai_gateway.agent.id
}

# Stamping commits the agent's name to its repository. The push starts the
# deploy workflow, now that its secrets and variables are in place.
resource "github_repository_file" "agent" {
  repository          = github_repository.agent.name
  branch              = "main"
  file                = "AGENT.md"
  content             = "# ${var.agent_name}\n\nStamped from ${var.github_owner}/${var.template_repo} by the agent golden path.\n"
  commit_message      = "Stamp ${var.agent_name}"
  overwrite_on_create = true

  depends_on = [
    github_actions_secret.cloudflare_api_token,
    github_actions_secret.cloudflare_account_id,
    github_actions_variable.agent_name,
    github_actions_variable.ai_gateway_id,
  ]
}

output "repo" {
  value = github_repository.agent.full_name
}

output "repo_url" {
  value = github_repository.agent.html_url
}
```

The repository starts as a copy of `agent-template`, deploy workflow included. The two variables are the agent's identity: `AGENT_NAME` becomes the Worker's name and `AGENT_ID`, and `AI_GATEWAY_ID` points the agent at its gateway from lesson 01. Nothing in the agent's code changes.

GitHub doesn't fire a push event when it creates a repository from a template. So the last resource commits `AGENT.md`, after the secrets and variables exist. Terraform commits with your GitHub token, and that push starts the deploy workflow.

## Run and verify

```bash
terraform apply
```

Then watch the deploy it started:

```bash
gh run watch --repo "$(terraform output -raw repo)"
```

Select the **Deploy agent** run. It installs, builds, and runs `wrangler deploy --name` with your agent's name and gateway. It takes about two minutes.

<Callout type="tip" title="No run?">
If `gh` finds no run, start one by hand: `gh workflow run deploy.yml --repo "$(terraform output -raw repo)"`.
</Callout>

When the run is green, open your agent:

```bash
terraform output worker_url
```

If you skipped lesson 02, the URL is in the run's summary on GitHub.

The header shows your agent's name and gateway, set by the workflow. Select **Write a file**, send it, and approve the write. Then check where the evidence lives:

- **AI Gateway**: open your agent's gateway, then **Logs**. Each model call shows `agent_id` and `user_id`.
- **Workers**: go to **Workers & Pages**, open your agent's Worker, then **Observability**. Traces show each request and the Durable Object work behind it. New traces can take a minute to appear.

## Success check

You are ready for the last lesson when:

- `terraform apply` finished with `6 added`.
- The **Deploy agent** run, started by the `Stamp` commit, finished green.
- Your agent on workers.dev shows its name and gateway, and its gateway logs your calls with `agent_id` and `user_id`.
